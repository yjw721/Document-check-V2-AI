# 知识库模块集成方案（RAG + 向量数据库 + OCR）

> 版本：v1.1 ｜ 适用：文档核验AI（本地离线部署）｜ 默认向量库：Chroma

---

## 一、总体架构

```
┌──────────────────────── 核验系统（既有，零改动） ────────────────────────┐
│  检测管理 / AI 核验 / 报告生成 / 规则词库 / 评估导航 …                     │
└───────────────┬────────────────────────────────────────────┘
                │ 只调用 service 门面（低耦合契约层）
┌───────────────▼──────────── 知识库模块 ─────────────────────────────────┐
│  service.py    对外门面：retrieve_for_verification / answer / tree       │
│  ───────────  编排层  ───────────────────────────────────────────────  │
│  engine.py     持久化 + 增量索引 + 混合检索 + 问答 + 防幻觉审计            │
│  prompts.py    内置 RAG 提示词（问答 / 核验辅助）+ 引用审计               │
│  tree.py       树形目录：建树 / 增删改 / 移动（含环路检测）                │
│  permissions.py 权限：与 settings.role 打通，服务端强制校验
│  graph.py      思维图谱：结构层级 + 跨章节概念关联（力导向可视化）                  │
│  records.py    使用记录：检索 / 问答历史持久化（逐条 + 整体管理）                │               │
│  ───────────  能力层  ───────────────────────────────────────────────  │
│  text.py       中文 bigram 分词 / 标题层级 / 重叠切片 / 上下文前缀        │
│  bm25.py       BM25 稀疏索引（一次建表，查询毫秒级）                      │
│  vectors.py    Ollama /api/embed 分批嵌入（失败自动折半重试）             │
│  fusion.py     RRF 融合 + MMR 去冗余 + 相关性闸门                        │
│  stores/       向量库抽象层：Chroma（默认）│ 内存 JSON（兜底）            │
│  parsers/      多格式解析：PDF(含扫描OCR)│Word│Excel│纯文本│图片OCR       │
└──────────────────────────────────────────────────────────────────────┘
```

**低耦合原则**：核验链路只 import `checkers.rag.service`，
换向量库 / 换 OCR 引擎 / 改切片策略，核验代码零改动。

## 三、权限模型

角色来源唯一：`config/settings.json → role`（与 AI 配置可见性共用）。
历史值 `user` 自动归一为 `operator`。

| 能力 | 说明 | 管理员 | 核验操作员 | 只读访客 |
|---|---|:-:|:-:|:-:|
| kb.view | 浏览目录树 / 文档列表 / 下载原文 | ✅ | ✅ | ✅ |
| kb.search | 检索、问答、核验联动检索 | ✅ | ✅ | ✅ |
| kb.upload | 上传文档、移动文档 | ✅ | ✅ | ❌ |
| kb.reindex | 单文档重向量化、全量重建 | ✅ | ✅ | ❌ |
| kb.delete | 删除文档、删除目录、删除/清空记录、清空知识库 | ✅ | ❌ | ❌ |
| kb.manage | 目录增删改、切片参数、后端切换、权限矩阵 | ✅ | ❌ | ❌ |

**强制点在服务端**：前端隐藏按钮只是体验优化，直接调接口会被 403 挡下：

```
POST /api/rag/clear   → 403 {"detail":"当前角色「核验操作员」无此操作权限：kb.delete"}
```

管理员可在「角色权限矩阵」里微调（写回 `knowledge.json → permissions`），
「恢复默认」一键还原。

## 四、内置 RAG 提示词

集中在 `checkers/rag/prompts.py`，便于按机构口径统一调整：

- **RAG_SYSTEM**（问答）：最高准则「只能依据资料」；引用规范（句末
  `[来源：文件名 / 章节路径]`，原样引用数字）；明确的拒答模板；
  禁止事项（不得自造文号 / 不得模糊表述绕过引用）。
- **VERIFY_SYSTEM**（核验辅助）：只对片段实际内容提意见；依据必须来自
  知识库并标注来源；未命中时说明「本次未命中可引用的知识库依据」；
  不得因库里有规定就断言报告违规。
- **audit_answer**（输出审计）：回扫回答中的来源标注，引用了资料中不存在的
  来源 → `grounded=false` 并给出告警；未标注来源 → 提示复核；
  可信度 = f(最高余弦, 命中段数)，前端展示为「可信度 N%」。

## 五、接口清单（核验流程 / 二次开发用）

### 低耦合门面（推荐）

```python
from checkers.rag.service import (
    retrieve_for_verification,   # 核验检索 → List[KbRef]（带出处）
    context_for_verification,    # 一步拿 (上下文文本, 引用清单)
    format_evidence,             # 引用清单 → 「知识依据」文本
    answer,                      # 带溯源问答（含可信度与告警）
    tree, permissions, is_enabled,
)
```

任何异常都被门面吞掉并返回空结果——**知识库故障不会拖垮核验主流程**。

### 思维图谱接口（GET /api/rag/graph）

在「本地知识库」页新增「知识思维图谱」区块，把知识库的结构与概念关联可视化：

- **节点**：`doc`（文档）与 `sec`（章节，由 `chunk.path` 以 ` / ` 切分得到，带层级 `level`）。
- **边**：`hierarchy`（文档→章节、章节→父章节，表达结构从属）与 `related`
  （跨章节概念关联：向量余弦 ≥ 0.55 时取语义相似；无向量时回退为关键词共现，
  共享高权重词 ≥ 2 个即连边）。
- **入参**：`folder`（限定目录子树）、`include_sub`（是否含子目录，默认 true）。
- **出参**：`{ ok, nodes, edges, stats }`，`stats` 含
  `docs / sections / related / hierarchy / has_vectors / nodes / edges`。
- **前端**：`KnowledgeGraph.tsx` 为纯 Canvas 力导向图（零第三方依赖），
  支持悬停高亮邻居、点击查看概念关联、拖拽节点、滚轮缩放、空白拖拽平移，
  并提供「重新布局 / 适应屏幕」按钮；`GraphDetail` 子组件展示选中节点的
  路径、样例文本、所属文档与关联章节列表。

### 检索 / 问答记录管理（`/api/rag/records`）

每次「检索诊断」与「知识库问答」在**返回结果之后**自动落盘一条记录，
写入失败一律吞掉异常，绝不拖慢或中断主流程（与门面「故障不传染」原则一致）。

- **存储**：`config/knowledge/records.json`（原子临时文件写入，进程内列表缓存，
  上限 `MAX_RECORDS=1000` 超限自动丢最旧）。该文件列入 `.gitignore`，属本机运行数据。
- **记录字段**：`id / type(ask|search) / ts / created_at / query / params / summary / result`。
  **列表接口不回传 `result`**（只给 `summary`）以省流量，`GET /{id}` 详情才回传完整载荷。
- **整体管理**：类型（`type=`）与关键词（`keyword=`，匹配 query 与 summary）筛选、
  分页（`limit/offset`，默认 50，上限 200）、时间区间（`since/until` epoch 秒）、
  整体统计（`total / ask / search / earliest / latest`）、清空（按类型或全部）、
  导出（`fmt=json` 原始结构｜`fmt=md` 可读 Markdown，含回答全文与命中片段表）。
- **逐条管理**：查看详情（问答含回答、可信度、审计告警与来源；检索含命中片段的
  RRF / BM25 / 向量得分与正文）、删除、以及**重新执行**（按记录的原 query 与 top_k
  再跑一次，结果回填到「检索诊断」/「知识库问答」卡片）。
- **前端**：`KbPage` 的「检索与问答记录」卡片 —— 工具栏做筛选 / 统计 / 清空 / 导出，
  每行一条记录带「重新执行 / 详情 / 删除」，`RecordDetailModal` 展示完整结果。
- **权限**：列表 / 详情 / 导出要求 `kb.search`；删除 / 清空要求 `kb.delete`，避免只读角色破坏记录。

> **实现注记**：`add_record / delete_record / clear_records` 内部对 `_cache` 重新赋值，
> 必须声明 `global _cache`，否则先前对 `_cache` 的读取会抛 `UnboundLocalError`
> 并被 `except` 静默吞掉——表现为「接口正常但记录永远写不进去」。
> 已由 `tests/regression/test_kb_records.py` 锁死（含上限裁剪分支）。

## 六、数据与部署

### 目录结构

```
config/knowledge/
├─ knowledge.json     文档元数据 + 分块文本 + 目录树 + 权限（唯一事实来源）
├─ files/             上传原文（供来源跳转下载）
└─ chroma/            Chroma 向量库持久化（DuckDB + HNSW）
```

向量不再写进 knowledge.json——纯 JSON 存 148 条向量时文件已 7.9MB，
迁移到 Chroma 后 knowledge.json 降到 KB 级，且检索不再受 `MAX_VECTORS=4000` 限制。

### 全新机器部署步骤

```bash
# 1. 安装依赖（内网离线机先在联网机 pip download -r requirements.txt -d wheels）
pip install -r requirements.txt

# 2. 安装 Ollama 并拉取中文优化模型（二选一即可）
ollama pull qwen3-embedding      # 推荐，307M，中文语义强
ollama pull bge-m3               # 备选

# 3. 启动
python app.py                    # http://127.0.0.1:8501

# 4. 打开「本地知识库」→ 上传文档 → 自动切片 + 向量化
#    状态徽章显示「向量检索可用 · qwen3-embedding」即成功
```

**优雅降级**：chromadb 未安装 → 自动退回内存 JSON 后端（纯 BM25 仍可用）；
Ollama 无嵌入模型 → 纯 BM25 检索；RapidOCR 未装 → 扫描件与图片拒绝入库并给出
安装命令。所有降级都会在界面上明确提示，绝不静默失效。

## 八、已知限制

1. **PDF 原文丢失的文档**：恢复场景下原文不在 `files/`，重建索引时改用
   已有分块文本重嵌（`reembedded` 计数），可检索但颗粒度停留在恢复时的切片；
   重新上传原文件即可恢复完整重切。
2. **旧版 .doc**：无 antiword/catdoc 时按二进制尽力抽取，失败会提示转存 .docx。
3. **Chroma 集合名**：≥1.0 强制 3~512 字符且仅 `[a-zA-Z0-9._-]`，
   非法名自动清洗回退默认 `docverify_kb`。
4. **OCR 置信度**：低于 0.45 的识别行直接丢弃，极模糊的扫描件可能识别不全。
